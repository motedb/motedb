# 向量化执行内核（VEC）实施计划

## 目标与验收总纲

| 指标 (100K×384 基准) | 现状 | 目标 | 对标 |
|---|---|---|---|
| equi-JOIN + GROUP BY | 16.7 ms | **< 4 ms** | DuckDB 1.2ms（收 14×→3×） |
| GROUP BY | 1.57 ms | **< 0.8 ms** | DuckDB 0.60 |
| 范围 COUNT+AVG | 0.76 ms | **< 0.4 ms** | SQLite 0.39 |
| 批量导入 (Python) | 62K 行/s | ≥ 200K 行/s | — |
| 手写 fast path 数量 | ~40 条 | **< 10 条** | 正确性红利 |
| 合并门槛 | — | 每里程碑: fuzz 20 seed 全绿 + 229 bin EXIT=0 + compete_bench 无回退 + E2E 51/51 | — |

**策略：绞杀者模式（strangler fig），不是重写。** 新建 `src/sql/vector_exec/` 模块与旧路径并存，一次收编一个查询形状，旧路径保留为回退，每个里程碑独立可交付、主线永远全绿。

## 核心设计

### 1. ColumnBatch 批结构（修复并收编现有 ColumnarRowSet）

`src/sql/vector_exec/batch.rs`（改造 `src/storage/row_format.rs:575` 的 ColumnArray）：

```
ColumnBatch { len, capacity=2048, cols: Vec<ColumnVector> }
ColumnVector {
  data: ColData,                        // Int64(Vec<i64>) | Float64(Vec<f64>) | Utf8(Vec<Arc<str>>)
                                        // | Bool(位图 u64 words) | Timestamp(Vec<i64>) | Values(Vec<Value>)  // 向量/空间 fallback
  valid: ValidityBitmap,                // u64 words, 修复现有 Null 丢值错位 bug (row_format.rs:855)
  sel: Option<SelectionVec>,            // 过滤后行号向量 (DuckDB 模式)
}
```

- 定长列批 2048 行；`Values` fallback 承接 VECTOR/GEOMETRY（knn 继续用现有 `&[f32]` SIMD 路径，不动）。
- Bool 改位图（现在 `Vec<bool>` 8× 浪费）。
- 预算接入：`CachedCol` 新增 `Batch` 变体实现 `heap_bytes()`，自动落入 store 现有 col_cache/vector_cache 预算（segment.rs:154 记账点，`trim_col_cache_to_budget` 零改动）。

### 2. 存储侧批读取 API（零 Value 物化）

`src/storage/col_segment/`：新增 `read_batch(col_idx, rows: &RowSel) -> ColumnVector`，直接从 `FixedSegment.raw_i64_slice()/raw_f64_typed_slice()/null_bitmap_bytes()`（columnar.rs:710-742，已存在）拷出定长批；Text 从 offsets+strings 批量切。替换三个已知浪费点：`scan_projected_filtered` 的 pvector 整列 `Vec<Option<Vec<f32>>>` clone（store.rs:935-950）、每行 `Vec::with_capacity`（store.rs:1053）、TS 三遍扫描（executor.rs:9609-9686，M1 顺手修）。

### 3. VectorExpr 批表达式 + 批谓词

`src/sql/vector_exec/expr.rs`：Expr → 批求值树（算术/比较/AND/OR/NOT 三值 Kleene 用 validity 位图算子/IS NULL/IN/BETWEEN/LIKE 前缀）。不可编译的子表达式**自动回退行式**（对 selection 中的行逐个调 `eval_expr_on_row`）——回退是策略不是失败。这是 `CompiledWhere`（executor.rs:1321）的泛化。

### 4. 批聚合 / 批 JOIN / 批排序

- `agg.rs`：无组聚合批累加（sum/min/max/count 批量循环，可自动向量化）；GROUP BY 用编码键 hash（多列键拼 128bit 或 hash+verify），组累加器批更新。NULL 语义矩阵照抄现有 fuzz 校准结果。
- `join.rs`：右侧批 build（键编码进 hash 表，值存行号批），左侧按批 probe，输出组合批——**不逐行 clone**。等值/ON 合取/谓词下推统一为"scan-filter 原语 + 批 hash"，替代 multi-way/positional/general 三套 join 的 inner 部分（LEFT/通用 SqlRow 路径保留为回退）。
- `sort.rs`：批 key 提取 + 索引排列排序；top-k 扩展现有 `top_k_row_indices_typed` 堆。
- `output.rs`：Batch → `QueryResult` 只在边界做一次行拼装，LIMIT 在拼装前截断（深分页/大投影的 Python 边界成本同步下降）。

### 5. 并行（M5，向量化之后做，收益相乘）

先拆三颗雷（探查确认的阻碍物）：
1. 共享 `query_executor` 的 params 竞态（api.rs:918 bind→execute→clear）→ 改为 per-query 上下文对象穿参；
2. `CURRENT_TXN_ID` thread-local Cell（executor.rs:1905）→ 并行闭包显式捕获传递；
3. `SPATIAL_KNN_MEMO/TEXT_MATCH_MEMO` thread-local（executor.rs:1909）→ 移入 per-query 上下文。

然后 morsel 驱动：段为工作单元喂 rayon（已是默认依赖，Cargo.toml:88），聚合 partial→merge，join 并行 build/probe。现有 `try_parallel_full_scan`（executor.rs:14620，>100K 行启用、先全量物化翻倍内存）由新框架吸收。

## 里程碑（每步独立交付，门槛建立在后）

| 里程碑 | 内容 | 验收（基准 + 全绿门槛） | 估时 |
|---|---|---|---|
| **M0 地基** | ColumnBatch/ValidityBitmap/SelectionVec 类型 + read_batch 存储 API + 修 ColumnarRowSet null bug + 单元测试矩阵（NULL/NaN/类型强转/Bool-Int） | 类型单测全绿；无行为变化 | 2-3 天 |
| **M1 扫描+过滤+无组聚合** | 批扫描/批谓词/批聚合接线，替换 FAST PATH 1a/1 fused + WHERE 全解码路径；TS 三遍扫描修复 | 范围聚合 0.76→<0.4ms；WHERE 扫描类 2×；fuzz 20 seed | 3-4 天 |
| **M2 GROUP BY 批聚合** | 替换 col_segment_group_by/single_pass_group_by/try_expression_group_by 三套 | GROUP BY 1.57→<0.8ms；GROUP BY 表达式 <2ms@100K；差分 10 形状 | 2-3 天 |
| **M3 批 hash JOIN** | 替换三套 inner join 快路径（含 ON 合取/下推统一） | JOIN 16.7→<4ms；JOIN 内存 <30MB@62 万组合行；fuzz 8 seed | 3-4 天 |
| **M4 排序/输出边界** | 批排序/top-k/批量输出拼装 + LIMIT 前置 | top-k 持平；全表投影输出 55→<25ms；深分页减半 | 2 天 |
| **M5 并行** | 三雷拆除 + morsel/并行聚合/join | 8 核 JOIN 再 2-3×；并发读压测无错果 | 3-4 天 |
| **M6 收编清理** | 删除被替代的旧路径（~30 条），executor.rs 拆为 scan/expr/agg/join/sort 模块文件 | fast path <10 条；229 bin 全绿；全基准复跑 | 2 天 |

里程碑间穿插：全量 fuzz（20 seed）、compete_bench、resource_bench（RSS 画像不得回退——批内存 = 2048×列数，有界）。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 语义回归（三值逻辑/NULL/类型强转——本轮 30+ bug 的教训） | 每里程碑 fuzz 门槛 + 向量化单元矩阵 + 旧路径保留回退开关（`MOTE_VEC=off` 环境变量，出事可即时切回） |
| 性能不升反降（小表/窄表批开销） | 批量 <128 行自动走旧行式路径（阈值实测校准）；compete_bench 门槛 |
| 内存画像回退（嵌入式定位） | 批固定 2048 行有界；缓存批进现有预算体系；resource_bench 对比 |
| 并行正确性（三雷） | M5 单独里程碑，先拆雷后并行；并发压测 + 现有 deadlock stress 测试 |
| 工期失控 | 绞杀者模式每步可停；M1-M4 完成即拿到 ~80% 收益，M5/M6 可独立排期 |

## 不在本计划内（明确排除）

ALTER/DDL、WAL/事务语义、存储格式变更（段文件不动，纯读侧）、向量化 knn（现有 SIMD 路径已领先）、DiskANN 稳定性（另线）。INSERT..SELECT/FROM 子查询等 SQL 缺口另线补。
