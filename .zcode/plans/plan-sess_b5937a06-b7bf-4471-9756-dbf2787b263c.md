## 向量距离计算优化：调用方改用 SIMD 内核

### 背景
`src/distance/` 有工业级 SIMD 实现（AVX2/SSE/NEON），但多处调用方绕过它手写标量循环，导致 `<->` `<=>` `<#>` 在 SQL 表达式执行时慢 4-8x。这是评估报告中 ROI 最高（投入小、收益确定）的优化。

### 改动

#### 1. 新增 `dot_product` SIMD 函数（`src/distance/`）
- `cosine.rs` 内部已计算 `dot_sum`（AVX2/SSE/NEON 累加器），提取为独立的 `pub fn dot_product(a: &[f32], b: &[f32]) -> f32`
- 复用现有的 SIMD 循环结构（dot 累加 + 水平求和），不重新写 intrinsics
- 在 `mod.rs` 导出 `pub use cosine::dot_product`
- 加单元测试（正交向量=0、相同向量=模长平方）

#### 2. evaluator 距离函数改调 SIMD（`src/sql/evaluator.rs:2297-2360`）
- `l2_distance`：`v1.iter().zip().map(|(a,b)|(a-b).powi(2)).sum().sqrt()` → `crate::distance::euclidean_distance(&v1, &v2)`
- `cosine_distance`：手写 dot/norm → `crate::distance::cosine_distance(&v1, &v2)`（零向量行为已一致：都返回 1.0）
- `dot_product`：手写 dot → `crate::distance::dot_product(&v1, &v2)`
- `extract_vectors`（行 2363）：保持返回 `Vec<f32>` 不变（避免生命周期复杂度；拷贝开销留作后续 #3 优化）。维数校验保留（SIMD 函数内部也有 assert，但提前返回更友好的错误）

#### 3. memtable 向量扫描改调 SIMD + 修距离混排 bug（`src/database/indexes/vector.rs:362-376`）
- Cosine 分支（行 363-369）：手写 dot/norm → `crate::distance::cosine_distance(vec_data.as_slice(), query)`
- Euclidean 分支（行 371-375）：手写平方和 → `crate::distance::euclidean_distance(vec_data.as_slice(), query)`
  - **顺带修 bug**：旧代码 Euclidean 返回平方距离（无 sqrt），但与 DiskANN 结果（真实距离）混在一起排序——平方距离和真实距离排序不等价。改为真实距离后一致。
- 用 `metric.distance(vec_data.as_slice(), query)`（DistanceKind 已有 Euclidean/Cosine，零成本分发）

#### 4. 验证
- 编译 release + debug
- 跑 `cargo test --lib`（含 distance 模块测试）确认 SIMD 函数正确
- 跑 `cargo test --test test_vector_spatial_text`（向量查询功能）
- 跑 `cargo test --test test_sql_correctness`（含 `<->` `<=>` `<#>` 操作符）
- 加一个微基准验证提速（可选：复用现有 bench 或简单计时）

### 不在本次范围（后续优化）
- `Arc<Vec<f32>>` → `Arc<[f32]>`（中 ROI，需改构造，单独做）
- `extract_vectors` 零拷贝（需 Value 生命周期重构，单独做）
- x86 SQ8 ADC 路径（需写 AVX2 intrinsics，单独做）
- Tensor::cosine/l2（无调用者，死代码，不改）

### 风险评估
- **低风险**：SIMD 函数已存在且经测试，只是调用方切换。语义已确认一致（零向量行为、距离 vs 平方距离的差异会修成一致）。
- memtable Euclidean 距离从平方改成真实是**行为变化**，但这是修 bug（与 DiskANN 结果一致排序），不影响正确性（排序结果更准确）。
