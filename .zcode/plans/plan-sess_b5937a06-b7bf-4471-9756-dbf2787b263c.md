## 精修和极致优化：修复 2 个 Critical Bug + 清理死代码 + 性能修复

### P0 BUG 修复（正确性，必须做）

#### BUG-1+2: read_fixed_i64_at 在 compact 模式下返回垃圾数据（columnar.rs:2087-2150）
**根因**：`file_data.is_empty()` 检查在 `flag==3` 检查之前。当 SSTable ≤8MB（file_data 已填充），compact 模式的 flag=3 segment 被当作 flag=0 直接按字节读 → 读到压缩字节当 i64 → 静默返回错误数据。`decompress_single_page` 是死代码（flag=3 分支不可达）。

**修复**：把 flag 检查提到 file_data 检查之前。`read_fixed_i64_at` 先读 flag byte，如果 flag ≥ 1（压缩），直接返回 Err 触发 fallback 到全列解码 + col_cache。flag=0 才走 O(1) 直接字节读。**这是最安全的修复**——compact 模式首次点查走全列解码（~ms），后续 col_cache 命中零开销。

### P1 性能修复

#### PERF-13: scan Box<dyn Iterator> 虚分发（store.rs:807）
用 `need_dedup` 分支直接写两个 for 循环（避免循环体重复用宏），消除虚分发。no-dedup 路径（最高频）恢复直接 `0..n` 循环。

#### WARN-15: Bool 谓词错失 i64 快速路径（executor.rs:10507）
在 i64 快速路径 guard 加入 `ColumnType::Boolean`（存储已是 0/1）。

### P2 死代码清理

- 删除 `bytes_to_i64_slice` / `bytes_to_f64_slice` / `i64_slice_to_bytes` / `f64_slice_to_bytes`（gorilla 写入暂缓后的死代码）
- `decompress_segment` 的 `col_idx` → `_col_idx`
- `SSTableCache::new` 加 `#[allow(dead_code)]`
- gorilla flag=4/5/6 解码分支加注释说明保留

### 验证
- release + x86_64 + fmt + clippy
- lib 430 + durability 17 + sql_correctness 59 + fast_paths 22
- **新增**：compact_storage=true 的 PK 点查往返测试（验证 BUG-1 修复）

### 风险
- BUG-1 修复只影响 compact=true（for_edge/robotics/embodied），默认 compact=false 不受影响
- col_cache 命中后性能不变（compact 模式首点查稍慢但正确）
